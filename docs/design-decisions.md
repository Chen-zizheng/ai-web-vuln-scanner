# 设计决策与取舍

这份文档记录每个关键决定背后的原因、付出的代价，以及如果重做会怎么改。
读它可以跳过逐行看代码，直接判断这些选择是否站得住。

## 1. 为什么不是「把网页丢给模型，让模型判断」

模型单次调用做不到三件事：给出可复现的行号路径、对同一输入稳定给同一结论、在不联网的前提下出结论。
所以分成两条轨道：

| 轨道 | 实现 | 确定 | 联网 | 结论强度 |
|---|---|---|---|---|
| 静态 | `taint.py` 来源→汇点数据流 | 结果逐字可复现 | 否 | 走通了数据流，带行号 |
| 模型 | `scanner_core.py` 特征→提示词→DeepSeek | 同输入可能不同输出 | 是 | 疑似，需人工复核 |

界面里这两段分开显示、分开计数，就是为了不让模型输出的不确定性污染静态结论的可信度。

## 2. 三个上限：1500 / 20000 / 2 MB

- `MAX_SCRIPT_CHARS = 1500`：单个 `<script>` 正文超过就截断并标注截掉多少。真实页面里大多数脚本块前几百字符就足以看出危险调用，后面是压缩后的库代码。
- `MAX_PROMPT_CHARS = 20000`：预算超了直接抛 `ValueError`，不组装请求。宁可不给结论，也不发出一个自己都不清楚内容的请求。
- `MAX_INPUT_BYTES = 2 MB`：在读文件之前用 `getsize` 拦，不先进内存。

代价：超过上限的页面会被拒，用户必须自己裁剪。这是有意的——一个 8 MB 的页面发出去，既是钱也是数据边界问题。

效果可量化：修复前 8 MB 页面会生成 9,321,064 字符的提示词；修复后同样的输入只生成 2,093 字符，并在结果里标注已截断。

## 3. 脱敏规则里的一个坑

`_SECRET_ASSIGN` 的正则最初写成 `\b(passwd|password|secret|token)=...`。
`DB_PASSWORD` 里的 `PASSWORD` 前面是下划线，不构成词边界，于是整条规则对最常见的命名方式失效。
去掉 `\b` 之后才真正匹配上。这类问题只有拿真实样本试才会暴露，靠读正则看不出来。

## 4. 为什么静态结论也要单独标一段

静态分析报的是「数据流走通」，不是「可利用」。典型例子：

```js
window.location.href = 'https://email.163.com?utm_source=' + location.host;
```

`location.*` 流向 `href`，规则会记一条 MEDIUM。但 `location.host` 是页面自己的域名，前面是固定前缀，没有注入点——这条是误报。
工具不知道前缀是常量，也不知道 `location.host` 的实际取值范围；把这类结论和「已证实」混在一起显示，会让使用者高估工具。

所以界面上写的是「静态分析 · 已证实」而非「确认漏洞」，并保留「需人工复核」的语义。

## 5. 汇点按属性名分级

同一个 `setAttribute`，风险差别很大：

| 汇点 | 级别 | 理由 |
|---|---|---|
| `setAttribute('onclick', x)` | HIGH | 直接变成可执行脚本 |
| `setAttribute('srcdoc', x)` | HIGH | iframe 文档内容 |
| `setAttribute('href', x)` | MEDIUM | 需要 `javascript:` 前缀才可利用 |
| `setAttribute('data-*', x)` | 不建汇点 | 纯数据属性，不参与解析 |

模板层同理：`v-html`、`[innerHTML]`、`dangerouslySetInnerHTML`、`{@html}` 是 HIGH；`{{{ }}}` 与 `unsafeHTML` 也归入。

- 第一轮 12 条：v1 污点分析 F1 0.2857，漏的全是框架语法。
- 第二轮 16 条：v2 补了模板汇点，F1 0.8889。
- 第三轮 16 条：v3 补了框架注入源，F1 0.8235，关键词规则 0.8421。

第二轮和第三轮都是在修上一轮暴露的问题，修完那一轮就不再是留出集。
所以文档里只把第三轮当作当前代码的成绩，前两轮降级为开发证据。把三轮成绩并排列出来更漂亮，但那是拿已经见过的题当考卷。

第三轮 McNemar 三个对比 p 值都是 1.0000：在这套语料的样本量下，关键词规则与污点分析的差异不显著。如实写出，不做过强结论。

## 7. 打包：onedir，不是 onefile

onefile 在目标机器上要先解压到 `%TEMP%`，在权限受限的环境里直接失败，启动也慢，杀软误报率更高。
换成 onedir（一个目录 + exe），代价是分发的是 zip 不是单个文件，收益是启动即用。

窗口版还有一个必须记住的坑：`--noconsole` 下 `sys.stdout is None`，任何 `print` 都会抛 `AttributeError` 并让进程静默退出。
所以启动时不再打印地址，而是写同目录的 `界面地址.txt`。

## 8. 本地网页界面的安全设计

exe 启动后监听 `127.0.0.1` 随机端口，浏览器打开带一次性 token 的地址。

- `token_urlsafe(18)`，`secrets.compare_digest` 比较，避免本机其他进程盲扫端口直接调接口。
- 校验 `Origin` 必须等于 `http://<Host>`，挡住恶意网页对本地服务的跨站请求。
- 抓取只允许 `http/https`、端口限 80/443/8080/8443，每跳都重新解析并校验 IP 是否为公网地址，禁止回环与内网。
- 最多 3 次跳转，单次 10 秒超时，正文读到 2 MB 截断。

遗漏：DNS rebinding 的窗口仍然存在（解析与连接之间），真实出口 IP 未做出口校验。

## 9. API Key 只走一次内存

界面里粘贴的 key 随这次请求体到 `127.0.0.1`，服务端取出后直接传给 `call_llm()`。
不落盘、不打日志、不进报告、不出现在返回 JSON 里；页面不写 `localStorage`，刷新即丢。
需要长期保存的用户自己配环境变量 `DEEPSEEK_API_KEY`。

## 10. 已知缺口（写在这里，不藏在心里）

- JSX 属性里的对象字面量、Svelte 的 `$page` store、Angular 的 `route.snapshot`、`__NEXT_DATA__` 尚未进来源表。
- 只覆盖 XSS 类汇点，不跨函数、不跨文件追踪，逻辑漏洞与越权不在范围。
- 不执行 JavaScript，纯前端渲染的站点抓不到内容，会给明确提示而不是给「0 条」。
- 误报来自「没有常量传播与上下文分析」，目前靠分级与人工复核消化。

## 11. 如果重做会改的三件事

1. 语料先于代码：先攒够真实站点页面，再写检测规则，避免自己出题自己考。
2. 加常量传播与简单净化识别，把 `location.host` 这类误报在内部消化掉。
3. 把评测做成 CI 的一步，每次改动都输出当前语料的 F1，防止在开发集上调参数调出幻觉。

## 12. 可能被追问的问题

**为什么用大模型？** 因为关键词规则在框架语料上召回只有 30%，而模型能覆盖没见过的写法。但模型给的是线索，静态分析给的是证据，两者不能互相替代。

**46% 的误报率怎么交代？** 那是关键词基线在开发集上的数字，不是当前工具的。当前工具按级别分层，静态结论可复现、模型结论标为疑似；把两者混在一起算一个准确率没有意义。

**凭什么说它准？** 三轮留出集、每轮独立标注、给出发 SQL 之外的可复现命令，并公开每一条误报的编号。数字可以被验证，也可以被反驳。
