# 评测集与评测流程

这个目录回答一个问题：**扫描器的风险判定到底准不准，准在哪、错在哪。**

没有这个目录之前，项目里只有“能用”的证据；有了它，才有“有多准”的证据。

## 数据集

`dataset.jsonl` —— 50 条人工编写、人工标注的 HTML 片段：

| 类别 | 条数 | 说明 |
|---|---|---|
| 正例 `xss-*` | 22 | 不可信输入确实可能进入可执行上下文 |
| 负例 `safe-001 ~ 016` | 16 | **有 sink 但数据源不可控**（`innerHTML` 写常量、`eval` 求常量、`src` 指向 CDN……） |
| 负例 `safe-017 ~ 028` | 12 | 无执行型 sink（表单、静态页、框架模板绑定） |

后两类负例是刻意设计的干扰项。**关键词规则会把 `safe-001 ~ 016` 全部误报**，这正是我们想测出来的东西。

## 标注规则

判定目标是「**页面是否存在 XSS 风险点**」，即：是否存在一条从不可信输入到可执行上下文的通路。

- 记为**正例**：存在 sink（`innerHTML` / `document.write` / `eval` / `setTimeout(字符串)` / `.src=` / `insertAdjacentHTML` / 内联事件处理器 / `srcdoc`），**且**其数据来自不可控来源（表单值、`location.*`、`localStorage`、URL 参数）。
- 记为**负例**：sink 存在但数据是常量/本地运算结果；数据来自不可控来源但只经由 `textContent` 或框架的自动转义绑定；页面无执行型 sink。
- `risk_level`：不可信数据直达执行上下文记 `HIGH`；需要一次额外交互或二次编码才可触发记 `MEDIUM`；无可执行通路记 `LOW`。

标注由人工完成，规则写在这里而不是藏在代码里，**任何人可以按同样规则复核我的标注**。有争议的样本应改标注而不是改规则。

## 运行

```bash
# 规则基线：离线，不花钱，秒出结果
python eval.py

# 真实调用大模型（需要有效的 DEEPSEEK_API_KEY）
export DEEPSEEK_API_KEY=sk-xxxx
python eval.py --backend deepseek

# 只跑前 10 条，快速验证链路
python eval.py --backend deepseek --limit 10
```

产物：

- `results.json` —— 逐样本预测 + 汇总指标，可复查每一条为什么判错
- `report.md` —— 可直接贴进 README 的表格
- `cache/<backend>.json` —— 模型返回缓存，重跑不重复计费

## 指标

| 指标 | 含义 |
|---|---|
| Accuracy | 整体判对比例（类别不平衡时会骗人，仅作参考） |
| Precision | 报出来的风险里有多少是真的 —— **这决定用户会不会被误报淹没** |
| Recall | 真实风险里抓到了多少 —— **这决定会不会漏放** |
| F1 | 两者的调和平均 |
| FPR | 误报率，`FP / (FP + TN)` |
| 字段完整率 | 模型输出里五个字段（类型/等级/位置/依据/建议）都非空的比例 |
| 等级一致率 | 判对的样本里，风险等级也一致的比例 |

## 当前结论

规则基线（命中 sink 即报 XSS）在 50 条上：**准确率 64%、精确率 56.67%、召回率 77.27%、F1 0.6539、误报率 46.43%**。

误报集中在 `safe-001 ~ 016`（有 sink 无 source），漏报集中在 `xss-004`（内联事件传参）、`xss-013`（jQuery `.html()`）、`xss-014`（`srcdoc`）、`xss-019`（`open()` 拼参数）、`xss-022`（`insertAdjacentHTML`）。

这两组错误指向两个明确的改进方向：**判断需要语义（谁的数据流进了 sink），而特征提取需要补齐 sink 覆盖**。
